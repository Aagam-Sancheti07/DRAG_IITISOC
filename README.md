# DRAG_IITISOC — Project Deimos / D.R.A.G.

Active-airbrake high-power sounding rocket simulation and pre-processing pipeline (6-inch, M-class motor, target apogee ~10,897 ft).

> **Note:** The Extended Kalman Filter (state estimation) — `StateTransitionFcn.m`, `MeasurementFcn.m`, and the EKF block inside `sixDOF.slx` — is documented separately in **`EKF_README.md`**. This README covers everything else: data pre-processing scripts, the Simulink flight models, and generated lookup tables.

---

## 1. Data Pre-Processing Scripts

These `.m` scripts take raw CSV exports (from the motor manufacturer, OpenRocket, or CFD/analytical work) and convert them into clean `.mat` lookup tables that the Simulink models pull into the workspace before running.

### `thrustcurve.m`
Reads the motor manufacturer's thrust data.
- **Input:** `Cesaroni_6026M1670-P.csv` — official Cesaroni 6026M1670-P motor thrust-curve export.
- **Extracts:** `Time`, `Thrust` columns.
- **Output:** `thrustcurve.mat` (`thrust`, `time`) — used by the 6-DOF/3-DOF models as the thrust-vs-time lookup during the burn phase.

### `dragcurve.m`
Reads the rocket's drag coefficient history.
- **Input:** `Cleandrag.csv` — cleaned Cd-vs-time data (post-processed, e.g. from CFD or OpenRocket).
- **Extracts:** `Time` → `time_c`, `Dc` → `Cd`.
- **Output:** `dragcurve.mat` (`Cd`, `time_c`) — baseline (0% airbrake deployment) drag coefficient lookup.

### `densityvsalt.m`
Builds the atmospheric density-vs-altitude table.
- **Input:** `altitude_density.csv` (`Altitude`, `density` columns).
- **Processing:** sorts by altitude ascending and removes duplicate altitude entries (`unique(..., 'stable')`) — both required because Simulink 1-D lookup tables need strictly increasing breakpoints.
- **Output:** `atmoData.mat` (`altitude_data`, `density_data`) — feeds the aerodynamic drag force calculation (`F_drag = 0.5 * ρ(alt) * V² * Cd * A`) at any altitude during flight, rather than assuming constant sea-level density.

### `openrocketdata.m`
Builds the time-varying mass/inertia/CG/CP properties table from an OpenRocket simulation export.
- **Input:** `openrocket_export.csv` — columns `Time`, `Mass`, `CGLocation`, `CPLocation`, `LongitudinalMOI` (Iyy), `RotationalMOI` (Ixx).
- **Processing:**
  1. Drops rows with `NaN` in Time/Mass/CG/CP.
  2. Sorts by time, removes duplicate timestamps.
  3. Finds where `CPLocation` drops to ≈0 (`cp_or <= 0.01`) — OpenRocket reports this once the rocket has left the "aerodynamically stable, ascending" phase (i.e., near/at apogee), so it marks where the useful ascent data ends.
  4. Truncates all arrays to 5 samples before that point (`cutoff_idx = apogee_idx - 5`) as a safety margin, discarding the post-apogee tail.
- **Output:** `rocketMassProps.mat` (`time_or`, `mass_or`, `cg_or`, `cp_or`, `Iyy_or`, `Ixx_or`) — feeds the mass, CG, and inertia values into the 6-DOF dynamics as functions of time (since motor burn continuously changes mass/CG during ascent).

### `Cpvsdep.m`
Builds the airbrake-deployment-vs-CP-shift lookup table.
- **No file input** — table values (`CP_shift_table`) are placeholder/example numbers in the script, meant to be replaced with actual CFD results (per the inline comment).
- **Table:** `deployPct_table = [0 25 50 75 100]` (% airbrake deployment) → `CP_shift_table = [0 0.02 0.05 0.09 0.14]` (meters, CP shift relative to 0% baseline).
- **Output:** `cpShiftData.mat` (`deployPct_table`, `CP_shift_table`) — used so the sim can account for the airbrake flaps shifting the center of pressure aft as they deploy, which affects static stability margin during the braked descent/coast phase.

### `trajectory.m`
Plotting script — visualizes the 3D flight path.
- **Expects in workspace:** `pos_braked` and `pos_unbraked` — each an `N×3` matrix of `[x, y, z]` position history (not generated by this script; must come from running the 6-DOF sim twice — once with the airbrake active, once "clean").
- **Output:** A single 3D figure overlaying both trajectories (blue solid = braked/airbrake active, red dashed = unbraked/clean), camera angled via `view(45, 20)` so both curves are visible. Used to visually confirm how much altitude the airbrake shaves off versus the unbraked case.
- **Note:** this script has no `save`/`function` wrapper — run it after both trajectories exist in your workspace, not standalone.

## 2. Raw Data Files (inputs)

| File | Used by | Description |
|---|---|---|
| `Cesaroni_6026M1670-P.csv` | `thrustcurve.m` | Manufacturer thrust-curve export for the Cesaroni 6026M1670-P motor |
| `Cleandrag.csv` | `dragcurve.m` | Cleaned Cd-vs-time data |
| `altitude_density.csv` | `densityvsalt.m` | Altitude vs. air density reference data |
| `openrocket_export.csv` | `openrocketdata.m` | Raw per-timestep mass property export from OpenRocket |

## 3. Generated Lookup Tables (outputs)

| File | Generated by | Contents |
|---|---|---|
| `thrustcurve.mat` | `thrustcurve.m` | `thrust`, `time` |
| `dragcurve.mat` | `dragcurve.m` | `Cd`, `time_c` |
| `atmoData.mat` | `densityvsalt.m` | `altitude_data`, `density_data` |
| `rocketMassProps.mat` | `openrocketdata.m` | `time_or`, `mass_or`, `cg_or`, `cp_or`, `Iyy_or`, `Ixx_or` |
| `cpShiftData.mat` | `Cpvsdep.m` | `deployPct_table`, `CP_shift_table` |

These five `.mat` files are the ones the Simulink models (`sixDOF.slx`) load into the base workspace before simulating — run the pre-processing scripts once before opening either model.

---

## 4. Simulink Models

### `sixDOF.slx`
Full 6-degree-of-freedom rigid-body flight simulation: 3 translational + 3 rotational states, driven by the thrust/drag/mass/CP lookup tables above. Includes:
- The IMU sensor model (simulated ADXL375/LSM6DSO32-style accelerometer + gyro, with configurable noise and bias) and MS5611 barometer model, feeding noisy measurements to...
- The EKF block for state estimation — **see `EKF_README.md`** for the filter design, tuning (Q/R matrices), and how the sensor models are configured.
- The active airbrake system (AAS), using `cpShiftData.mat` to account for CP shift with deployment.

---

## Suggested Run Order

1. Run the five pre-processing scripts once (`thrustcurve.m`, `dragcurve.m`, `densityvsalt.m`, `openrocketdata.m`, `Cpvsdep.m`) to generate the `.mat` lookup tables from your raw CSVs.
2. Open `sixDOF.slx` (full sim + EKF) or `threeDOF.slx` (quick point-mass trajectory) — both load the `.mat` files from the base workspace.
3. If comparing braked vs. unbraked flight, run the sim twice (with/without airbrake active), capture `pos_braked` and `pos_unbraked`, then run `trajectory.m` to plot both.
